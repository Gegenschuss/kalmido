# Tests

Black-box tests against a real Kalmido container: the Python suites talk to the HTTP API, the JavaScript
suites load the actual web app in [jsdom](https://github.com/jsdom/jsdom) (no browser needed) and click
through it. Every group starts a **fresh** container with an empty database, so nothing here ever touches
your own data.

## Run them

Requirements: Docker, Python 3.10+ and Node.js 18+ (for `fetch`); Firefox for `scroll_ui.js` (skipped without it).

```sh
cd tests
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
npm ci
BUILD=1 ./run_all.sh          # builds kalmido:test from the repo, then runs every suite
./run_all.sh --shard 2/4      # only the 2nd of the 4 shards (CI: 4 parallel jobs, ~15 min each)
```

`run_all.sh` prints one summary line per suite and exits non-zero if anything failed. Single suites:

```sh
./start.sh                      # fresh container on 127.0.0.1:3041 (proxy port) and :3048 (app port)
python3 api_test.py .data       # most Python suites expect a fresh container + the data dir
node ui_test.js                 # after api_test.py (uses its ids.json)
```

Settings (environment variables, all optional):

| Variable | Default | |
|---|---|---|
| `KALMIDO_TEST_IMAGE` | `kalmido:test` | image to test |
| `KALMIDO_TEST_CONTAINER` | `kalmido-test` | container name (removed and recreated) |
| `KALMIDO_TEST_PORT` | `3048` | host port of the app port (built-in login) |
| `KALMIDO_TEST_PROXY_PORT` | `3041` | host port of the proxy port (trusts `Remote-User` from the Docker gateway) |
| `KALMIDO_TEST_DATA` | `tests/.data` | data dir bind-mounted to `/data` (wiped per group) |
| `PYTHON` | `python3` | interpreter for the Python suites |
| `KALMIDO_ONBOARDING` | `0` | `1` = new accounts get the sample list + welcome tour (the 1.1 suites set it themselves) |
| `KALMIDO_ADMIN_ALERTS` | `0` | `1` = admin alerts via ntfy on (the admin alerts suite sets it itself) |

The container runs as your own user (`--user $(id -u):$(id -g)`), so the tests can read the database and
the stub logs in the data dir. It gets `KALMIDO_UPDATE_CHECK=0` (no requests to GitHub) and a stub ntfy
server inside the container that logs every push to `.data/ntfy.log`.

## Writing tests

- Keep them black-box: HTTP API or the real UI in jsdom. Reading the SQLite file directly is fine for
  assertions and for setting up states that are hard to reach otherwise.
- Every check prints `FAIL: ...` and the suite ends with `N ok, M failed` and exit code 1 on failures.
- New user-facing strings need a German translation (`python3 tools/i18n_check.py`), the UI tests run
  in English and German.
